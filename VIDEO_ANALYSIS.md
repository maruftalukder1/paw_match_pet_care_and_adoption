# Phase 3 — Video symptom analysis for the Symptom Checker

Status: **BUILT and TESTED, source only, NOT published, NOT deployed.**
Artifact untouched, GitHub untouched.

## What was built

**1. Edge Function `supabase/functions/analyze-video/index.ts` (+ README.md)** —
mirrors `analyze-photo`:
- Same CORS headers, same `GEMINI_API_KEY` server secret (ALREADY SET in the
  project — **no new secret needed**), same model pins
  (`gemini-3.7-flash` primary, `gemini-3.1-flash-lite` fallback on 429/503),
  same generation config (`maxOutputTokens: 2048`, `thinkingConfig:
  { thinkingBudget: 512 }`), same server-enforced disclaimer.
- Input: `{ framesBase64: string[] (1..6), mimeType, species, symptoms[],
  durationSec }`. Rejects >6 frames, per-frame cap (~1.5 MB base64), total
  cap (6 MB), non-image mime types, with clear errors.
- Video-specific system prompt: observe ACROSS the chronological frame
  sequence — gait/limping, posture changes, breathing effort, activity level.
  Returns `{ observedSigns[], triageHint, sequenceNote, vetQuestions[],
  disclaimer }` — `sequenceNote` is one line on change across the frames
  ("no change visible across frames" if none). Red flags force emergency
  exactly like the photo prompt. Observations only, never a diagnosis, no
  medications. SAFETY finish → typed 200 error (not a silent drop).

**2. `src/lib/videoAnalysisCore.ts`** (new, import-free of the Vite client so
headless unit tests can run it) — constants, `VideoAnalysisError`, video
`validateVideoFile()`, `videoNoteSummary()` (history note prefixed `"Video:
"`).

**3. `src/lib/videoAnalysis.ts`** (new) — the frame pipeline + single invoke
call site:
- `extractVideoFrames(file, n)`: `<video>` + canvas seeking, up to
  **6 frames** spread at the centers of equal slices of the clip
  (chronological), downscaled to ≤1000 px longest side, JPEG 0.85 — the same
  recipe as ImageUploader. Per-frame base64 cap enforced client-side. **The
  raw video file never leaves the device.**
- `getVideoDurationSec(file)` for the preview line; `analyzeVideo(input)`
  invokes `analyze-video` and converts every failure into a typed
  `VideoAnalysisError`.

**4. `src/components/SymptomChecker.tsx`** — Step 5 is now "Add a photo or
video (optional — AI observations)" with Photo/Video tabs:
- The photo flow is **unchanged** (same ImageUploader, same wiring,
  same history behavior).
- Video pane: file picker (`accept="video/*"`, MP4/WebM/MOV, ≤100 MB),
  `<video controls muted>` preview, clip duration + "6 frames will be
  sampled across it", remove button, the privacy line ("your video stays on
  your device — only a few sampled still frames are analyzed"), guidance
  (~60 s clips work best), and fine print: "Sampling can miss things that
  happen between frames — this is not continuous video analysis."
- Photo and video are **alternatives for one check**: attaching one clears
  the other; the media tab follows the attachment.
- On check with a video: rule result renders first (always), then frames are
  sampled → `analyze-video` → an "AI video observations" card merges in
  (signs, **sequenceNote**, vet questions, server-enforced disclaimer).
- **Escalation only**, like photos: an AI `emergency` hint shows the pulsing
  banner (with "The AI video analysis spotted…" reason) and EMERGENCY card;
  a lower hint never changes the band.
- ANY failure (decode error, seek timeout, function down, secret missing)
  → one honest line: "Video analysis isn't available right now — your check
  above is unaffected." The check never blocks. History `photoNote` carries
  the video summary (camera icon, "Video:" prefix).

## Honest limits

- **Not machine-proven against the real deployed function + real Gemini
  response** — the function is not deployed yet. The stub proves the client
  wiring; frame extraction is proven with real video decoding; the prompt
  shape follows the live-proven `analyze-photo` pattern.
- Frame sampling **can miss events between sampled frames** — stated in the
  UI fine print; this is not continuous video understanding.
- `videoNoteSummary` reuses the history `photoNote` field (already existed) —
  no schema change; a UI copy choice, documented here.
